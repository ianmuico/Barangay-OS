## Template System Architecture

### Three tag types:
```
{{variable}}           → Auto-filled from resident/case data (existing: fullName, age, address, etc.)
{{input:fieldName}}    → Shows a text input box when generating the report (e.g., hearing_date, case_description)
{{signatory:role}}     → Pulls from officials table; for rotating roles like kagawad_on_duty, shows a picker dropdown
{{header}}             → Inserts the standard barangay letterhead (logos, Republic of PH, province, municipality, barangay name)
```

### Example summons template:
```
{{header}}

SUMMONS

To: {{fullName}}
Address: {{address}}, Purok {{purok}}

You are hereby summoned to appear before the Lupon Tagapamayapa
on {{input:hearing_date}} at {{input:hearing_time}} regarding:

{{input:case_description}}

Failure to appear shall {{input:consequence}}.

{{signatory:punong_barangay}}
{{signatory:kagawad_on_duty}}
```

## Cases & Summons Data Model

```
cases
├── id INTEGER PRIMARY KEY
├── case_number TEXT UNIQUE (auto-generated: YYYY-NNN)
├── case_type TEXT (mediation, complaint, dispute, etc.)
├── complainant_id INTEGER → residents
├── respondent_id INTEGER → residents
├── description TEXT
├── status TEXT (pending, ongoing, resolved, dismissed)
├── filed_date DATE
├── resolved_date DATE (nullable)
├── resolution_notes TEXT (nullable)
├── created_at, updated_at

summons
├── id INTEGER PRIMARY KEY
├── case_id INTEGER → cases
├── summoned_resident_id INTEGER → residents
├── summon_number INTEGER (1st, 2nd, 3rd)
├── summon_date DATE
├── summon_time TEXT
├── status TEXT (scheduled, served, appeared, no_show)
├── served_by_official_id INTEGER → officials (nullable)
├── notes TEXT (nullable)
├── created_at
```
